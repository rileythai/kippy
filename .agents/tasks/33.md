# 33: Split kipp.f90 into modules under the public kipp module

status: open
opened: 2026-11-06

## Goal

`kipp.f90` (2607 lines, 23 module variables) becomes small modules with one concern each, so a reader can see each routine's inputs and outputs. `kipp` stays the only module `convview.f90` uses, with the same public API. Done when every step passes the task 32 harness byte-identical.

## Spec

Modules (approx line ranges in the current `kipp.f90`):

- `kipp_state`: `kstate_t`/`st`, model axes (`xval`, `xedge`, `ystar`), render globals, constants.
- `coords`: `xtrans`, `ytrans`, `ytrans2`, `inv_x/y`, `mbound`, `bisect_le`, `build_axes`.
- `bands`: tracer, bandset and chain types and routines (1384-1928). Aim: no giza dependency.
- `layers`: field/energy lookup, `level_intervals`, cache builders, `cache_invalidate`.
- `draw`: giza drawing (`draw_scene`, bands, surface, grid, models).
- `cursor`: `kipp_interact`, `kipp_action`, view history, zoom/pan, `print_cell`.
- `kipp`: thin public module, re-exports today's API.

Doc standard: a header per module (purpose, inputs, outputs, state read/written); FORD `!!` docstring after each procedure line, a `! Arguments` block, and a `!!` line under each argument. FORD `warn: true` reports undocumented procedures and arguments (checked on a test module 2026-11-06).

Decisions (2026-11-06, user):
- Scope is `kipp.f90` only; `mesaload.f90` is task 34.
- Plain modules, short names as above (no clash with existing identifiers, checked with `grep -w`).
- Move-only first (globals into `kipp_state`), then convert to explicit arguments piece by piece.
- Comments are wanted for this code; only comments that add nothing are unwanted.
- Inner API docs generated by FORD for the zensical site.

Decisions (2026-11-06, user, second round):
- Ticks, labels and colorbars get their own `axes` module.
- FORD `warn: true` is the doc check; no findent (it flattens the indented `!!` argument lines, findent 4.3.6 has no option to keep them).
- FORD runs through `uvx` in a mise task; nothing added to pyproject or uv.lock.
- FORD writes HTML only, so the zensical site links a FORD output directory. Try it and see.

Decisions (2026-11-06, user, third round):
- Doc gate is `tools/doccheck.py`: a `!!` docstring for every module, procedure, argument, module variable and type component. Locals are not checked. FORD 7.0.13 `warn` also flags locals, so it only builds the HTML.
- Cycle fix: `kipp_render` and `kipp_save` move to `draw`, `kipp_autoscale` to `coords`; `kipp` re-exports them under the same names.
- `kipp_state` holds only the entities several modules use: `kstate_t`/`st`, `nmodels`, `xval`, `xedge`, `ystar`, `chs`. Every other entity moves with its one owner. Order: `kipp_state`, `bands`, `coords`, `layers`, `axes`, `draw`, `cursor`.
- `profiles_fixture/` stays untracked (not committed, not gitignored) until the user sets up LFS and a real test suite. The user adds the missing MESA columns to its profiles.

Decisions (2026-11-06, user, fourth round):
- The `kipp_state.f90` doc style is approved for every module: a FORD module docstring stating what it holds and who reads or writes it, a sentence-case `!!` line under each entity, plain `!` comments lower case.
- FORD pages are served under the docs site as `<site>/fortran/...` (kippy.rileythai.com/fortran/), from `site/fortran`.

Decisions (2026-11-06, user, fifth round):
- Docstring language follows the user's `bands.f90` rewrite: a short summary line, then one brief sentence per line in scientific style, with notes that expand opaque names. Rules: `~/.claude/rules/docstrings.md`.

Decisions (2026-11-06, user, coords step):
- `build_axes` no longer allocates `epx`/`epy`; `draw_scene` calls `ensure_scratch(4*nmodels + 4)` once per render, so the scratch stays with `draw`.
- `xoff` is a public variable of `coords` (a parameter of the x transform), written by `draw_scene`; `xofftxt` stays with `draw`.
- `coord_at` goes to `coords` beside `mbound`. `yscale` and `LOGMIN` go too (forced: `ytrans` uses both, nothing else uses `LOGMIN`).

Decisions (2026-11-06, user, convection type names):
- No magic numbers for convection types. Named codes RADIATIVE, NEUTRAL, OVERSHOOT, SEMICONV, CONVECTIVE, THERMOHALINE, NCONVTYPES and the yzip characters ZONE_CHAR live in convdata.f90, used by the renderer and the readers.
- The reader input codes get names too: MESA mixing types after const_def.f90 (r26.04.1 lines 158-167), MONASH kcvtn as MON_RADIATIVE 0, MON_CONVECTIVE 1, MON_SEMICONV 2 (the isemi gap, amanda phys.f), MON_OVERSHOOT 3. Mappings unchanged (kcvtn 2 still draws as convective).

Decisions (2026-11-06, user, axes step):
- `colormap` and `is_reversed` go to `axes`, public (forced: `draw_field_colorbar` uses `colormap`, and `draw` will use `axes`). `draw_field` and the cmap selection import them from there.

Decisions (2026-11-06, user, draw step):
- `set_time_unit` goes to `coords` (forced: draw_scene and kipp_set_unit both call it); `set_y_units` stays in `kipp`.
- `kipp_choose_device` and `kipp_close` go to `draw` beside `kipp_render`/`kipp_save`; `kipp` re-exports them.
- `list_index`, `kipp_set_cmap`, `kipp_list_cmaps` stay in `kipp` (not forced; REPL setters like `kipp_set_unit`).
- `clamp_view`, `ybound_lo`, `clamp1`, `set_visible_range`, `ivis0/ivis1` go to `draw` (one owner: draw_scene and the band emitters).

Decisions (2026-11-06, user, cursor step):
- `kipp_wait_input` goes to `cursor` with `c_isatty`, so `kipp` drops `giza` and the C bindings.
- `views` and `view_t` stay private to `cursor`; a public `clear_views` empties the history and `kipp_rebuild` calls it.

Decisions (2026-11-06, user, kipp docs and site):
- Drop the unused `fieldlayer` import from `kipp`.
- FORD writes to the gitignored `docs/fortran`, which zensical copies to `site/fortran` (supersedes "from `site/fortran`" above: `zensical build` wipes `site/`, and serve only serves its own build). `docs:build` and `docs:serve` depend on `docs:fortran`; docs.yml runs FORD before zensical.

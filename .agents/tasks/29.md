## Goal

Merge branch `field-scale` (`9a910f5`) into main. Done when `color -N` works from main and the default-scale renders are unchanged.

## Spec

The branch PLAN.md calls this task 23, which clashes with main's 23 (unit system). Main deletes PLAN.md, so the merge hits a modify/delete conflict on it: keep the delete, the branch's entry is copied here.

From the branch PLAN.md: `build_field_layer` bins every column field in both scales at load (`fld(2, nf)`: default scale, then the other; `fcache(2, nf)` to match), so `color -N` (`st%cflip`) switches instantly; `color N` or a name returns to the default scale. A log scale starts at `field_vpos`, the smallest positive value in the run, and values <= 0 fall in bin 1; a field with no positive values refuses `-N`, as do the fixed selectors `-1..-3`. Default-scale binning is unchanged (vpos equals vmin for a default-log field). Verified: `.scratch/flip_check.f90` checks both layers against hand-computed bins; `.scratch/verify_flip.sh` renders every column field of a real `.kipp` (atse p48 hg), the seq fixture and a MESA dir (blueloops 5) with a HEAD build and this one: all 24 default-scale PNGs byte-identical to HEAD, every accepted `-N` differs, the two all-non-positive seq rates refused. Not checked in a live `/xw` window; `tools/smoke_test.py` not run.

Decision (2026-10-20, user): bin both scales at load (not reload on switch), log floor at the smallest positive value (not fixed decades or refuse), reject `-1..-3`. Instant switch from the shared `build_field_layer` for every reader at roughly twice the field-layer memory.

Build note (2026-10-20): `build/cp312`, the editable install's build dir, held `.mod` files from a newer gfortran (module version 16; system gfortran 13.3 writes 15), so ninja failed there until it is wiped and rebuilt. That session built in `.scratch/bld-flip` instead.
